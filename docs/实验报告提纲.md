# 山东大学场馆预约管理系统实验报告提纲

本文件按课程要求整理报告结构，供开发过程中持续补充。未完成内容须在实际实现后填写，截图和进度以最终系统为准。

## 1 总体描述

系统面向学生与校园场馆管理员，围绕场馆查询、时段预约、审核、取消和签到组织业务。补充需求背景、使用场景、实际完成范围和特色。

## 2 人员分工

待补充团队成员、各自负责模块和具体贡献。每位成员还需在课程网站单独填写个人贡献。

## 3 项目进度

当前完成基础框架。按实际时间补充需求、设计、实现、联调、测试、部署和报告安排。

## 4 需求分析

功能需求：身份认证、权限隔离、场馆查询和筛选、预约提交和冲突检查、审核取消、签到、场馆维护和预约统计。

非功能需求：浏览器访问、敏感字段不返回、接口鉴权、CSRF 防护、数据库事务及并发冲突处理。性能指标和测试结果需实际测量后填写。

## 5 系统功能架构

参考 `系统设计.md`，补充学生端、管理端功能架构图和 Vue → HTTP API → Spring Boot → MySQL 通信说明。

## 6 实体关系图

参考 `系统设计.md` 的实体 UML，补充 AppUser、Venue、Booking 字段与一对多关系，按最终数据库结构更新。

## 7 主要代码说明

选择少量核心代码说明，例如预约冲突事务、角色权限和签到时间窗；避免堆叠全部源码。

## 8 系统整体实现

补充登录、工作台、场馆列表、时段预约、预约记录、场馆管理的真实截图与操作流程。

## 9 系统特色实现

可说明可视化时段选择、数据库并发控制、角色数据隔离、真实预约统计与响应式页面。只写最终完成且可演示的特色。

## 10 环境运行与部署

课程说明中，Spring Boot 按规范部署可不填写该项。其他部署方式需详细说明环境、运行和测试过程。在线验收使用 JDK 21、22222 端口、课程 MySQL，上传指定名称的 JAR。

## 11 系统总结

结合实际开发过程总结设计取舍、团队协作、问题解决、测试结果及改进方向。
